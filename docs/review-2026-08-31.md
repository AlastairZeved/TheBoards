## 1. What this is (verified from the running app, not just the docs)

A bounded, dark, spatial to-do PWA. One logical sheet, one uniform
`transform: scale()`. Four permanent anchors (Title compartment, Components,
Requirements, Parking Lot); free notes anywhere between the two water sections.
Tap-to-capture, drag-to-move, pinch-to-scale, scratch-out completion, 5-second
undo, hand-rolled vector PDF export, four board-type ladders (To-Do blue, Idea
green, Note violet, Learning rose) that rotate hue while pinning luminance.

The design is genuinely unusual and genuinely disciplined: the palette is a
*computed* system (WCAG relative luminance held to 4 decimal places across a
hue rotation, verified by a 396-assertion test), and the docs (`PRD`/`UIUX`/
`DECISIONS`) are the most rigorous design-governance records I have seen in a
repo this size. `DECISIONS.md` is a numbered case law of 90 rulings.

## 2. Architecture assessment

**Five files, no dependencies, no build step — and the discipline holds.**
`app.js` (3,738 lines) is the entire logic in 12 numbered sections with a
header map. Verified working:

| Subsystem | Verdict |
|---|---|
| Persistence (§2–3) | IndexedDB single-flight queue, debounced 300ms, exponential backoff, flush-on-exit that stamps `updatedAt` only when dirty. Clean and correct. |
| Layout (§4) | Viewport-derived logical space (mobile `renderScale=1`, desktop `min(vh/1000,(vw−300)/900)`), similarity transform (B64) for cross-device rendering. Sound. |
| Gestures (§7–8) | One recognizer, `isDesktop` capability branch, compatibility-event suppression at source (B27). The subtlest code in the repo; the comment density here is earning its keep. |
| Undo (§9) | Exact-state restore incl. array index; batch = one window. Correct. |
| PDF export (§10.5) | Hand-rolled writer with xref table; completed items emit no text object (the on-screen privacy promise becomes a property of the bytes). Genuinely impressive. |
| Routing (§11) | History API only; OS back gesture works; two-level drill state. |
| Service worker | Stale-while-revalidate + `reg.update()` on visibilitychange (B79) — the "deploy lands in a launch or two" story is real. |

**Code quality:** consistently high. Comments cite doc sections and ruling
numbers, so every line's *why* is recoverable. Names are good. The single-file
size (~187KB) is at the edge of comfortable but is a documented, deliberate
trade (§3.3 forbids a bundler), and the section map mitigates it.

### Bugs / real risks found

1. **`sanitizeBoard()` collides with an in-flight editor's note.** B31 sweeps
   whitespace-only records on *every render* — correct — but `renderBoard()`
   runs on `visibilitychange`-adjacent flows (board swaps, pane renders). A
   note whose text node is mid-edit is protected only because its text lives
   in the DOM, not yet in `current.notes`. The save debounce is 300ms; a
   render that fires inside that window reads a stale `note.text === ''` and
   deletes a note the user is actively typing into, on the next render. Low
   probability (the same 300ms window is also when the DOM re-render would
   blow away the caret anyway) but it is a data-loss shape, and the sweep has
   no "skip the note currently being edited" guard. **Add an isEditing check
   to the sweep.**
2. **`newBoardRecord()` omits `catStamp`.** B69's sort key is
   `max(updatedAt, catStamp) floored at createdAt`; a fresh board relies on
   `updatedAt` being set (it is), so this is currently benign — but the
   `flushSave()` comment warns about exactly this kind of two-skins drift.
   Cheap to harden.
3. **`sw.js` `fetch` handler caches `?`-suffixed URLs unbounded.** `c.put(req, …)`
   keyed on the full URL means a querystring change fragments the cache; the
   activate cleanup only deletes non-current *cache names*, not entries. With
   `start_url: "."` this is theoretical today, but it is the one place the
   delivery net has a hole.
4. **Test coverage is exemplary for behavior, silent on two shipped surfaces:**
   `UIUX §12` accessibility beyond focus rings (§16.3 says "nothing" pins §8
   motion and §12 — the docs admit it), and the four ladders' *rendered*
   output (tokens.js checks the math, not the pixels). The docs call this out
   honestly; it remains the largest quality gap.

**App Store readiness (the literal question):** as a PWA it is already
installable and store-wrappable (TWA for Play, orPWAs via WebView for the App
Store wrapper tools). The technical gates are met: offline-complete,
manifest with maskable icon, standalone display, `orientation: any` for
foldables. What an App Store review would flag is experience gaps, not
technical ones — which is what the mockups address.

## 3. Store-worthiness gaps (what the mockups address)

These are the *only* weaknesses I found in the visual system, verified live:

1. **The capture loop is discoverable but not *teachable*.** The empty board
   is deliberately blank (correct, P4), but a first-run person has no way to
   learn tap-to-capture except by accident. PRD §1.3 says no onboarding
   *overlay*; it does not forbid the board *itself* demonstrating the gesture.
2. **First-frame brand moment is spent on OS chrome.** Splash/launch is
   `#020812` flatness — correct for the room metaphor, but the launcher icon
   (B1's note motif) is the only branded pixel; the splash is a missed
   free beat.
3. **The note toolbar tabs are the one cramped surface.** Verified in the
   desktop screenshot: four 18px-glyph tabs ride a small note; on mobile the
   row covers the note's first text line when flipped. The B86 sizing helps
   but the row still reads as UI stuck onto the note rather than growing from
   it.
4. **The "PDF export check" note kisses the right edge.** Verified: B39's
   wrap-at-edge law lets a dragged note's frame touch the sheet edge with 0px
   of ink visible. Stored positions are permanent (P3 — you cannot re-clamp),
   but the *render* can inset by a hairline without touching data.
5. **The Parking Lot header floats on open water with no second anchor.** The
   band's headers hang from their rule; the lot's header hangs alone at
   `top: 8px`. Small asymmetry between the two "mirror" sections.
6. **`apple-mobile-web-app-*` metas are iOS-minimal.** No
   `apple-touch-startup-image`, so iOS adds its own launch transition against
   your theme color — the one place the app's calm-water identity is
   interrupted by platform default.
7. **Category tiles in the 2×2 grid show the rotated ladders beautifully but
   have no count/state.** An empty category and a 30-board category render
   identically — P4 says the interface asks nothing, but a card that previews
   its board could preview its *fullness* structurally (a tiny lot-line
   glyph), not with a badge number.

## 4. What must NOT change (the binding constraints any v3 obeys)

- The water field, the deep, the luminance-pinned ladder rotation (§2.2.2).
  Hue is scene; luminance is law.
- The note as the brightest surface; `--danger` as the only warm hue.
- No shadows on notes. Elevation is for summoned surfaces only.
- Scratch-out completion with text burial (§4.3) — non-negotiable product
  identity.
- Tap-to-capture with zero latency (§5.6, B81); no modes, no dialogs.
- No settings, no accounts, no badges-as-demands (P4).
- The touch floor (44px) and the two-tone focus ring (§2.7).
- Motion stays a closed set of five (§8).
